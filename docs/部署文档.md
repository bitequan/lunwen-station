# 部署文档

本文档描述在全新服务器（推荐宝塔面板）上从零部署本系统的完整流程。

## 一、环境要求

| 组件 | 要求 | 说明 |
| --- | --- | --- |
| PHP | **8.0.x** | 必须为 8.0 系列；扩展需启用 `fileinfo`；**无需 Redis**（缓存为 File 驱动） |
| MySQL | 5.7+ | 创建一个空数据库即可，字符集 utf8 / utf8mb4 均可 |
| Web 服务器 | Nginx / Apache | 运行目录必须指向 `public` |
| 磁盘 | ≥ 2GB | 含 vendor 依赖与前端静态产物 |

## 二、宝塔面板部署步骤

### 1. 创建站点

1. 宝塔 →「网站」→「添加站点」：
   - 域名：填你的域名
   - PHP 版本：**8.0**
   - 数据库：选择 MySQL，勾选「自动创建数据库」（记下库名/账号/密码）
2. 进入站点设置 →「网站目录」：
   - 运行目录：**`/public`**
   - 关闭「防跨站攻击(open_basedir)」或按需保留（保证 `public` 上级目录可读）
3. 站点设置 →「伪静态」，选择 `thinkphp` 模板，或粘贴：

```nginx
location / {
    if (!-e $request_filename) {
        rewrite ^(.*)$ /index.php?s=$1 last;
        break;
    }
}
```

（可选，前端 404 更友好）追加：

```nginx
location /pc/ {
    try_files $uri $uri/ /pc/404.html;
}

location /m/ {
    try_files $uri $uri/ /m/404.html;
}
```

### 2. 上传代码

1. 将安装包内**全部文件**上传到站点根目录（如 `/www/wwwroot/你的站点/`）
2. 确认目录结构：站点根目录下应能看到 `app/`、`config/`、`public/`、`vendor/`、`data/` 等
3. 设置可写权限（宝塔默认 www 用户一般无需调整）：
   - `runtime/`（运行时缓存，自动生成）
   - `public/uploads/`（用户上传文件）
   - `.env`（安装向导写入）

### 3. 运行安装向导

浏览器访问：

```
http://你的域名/install.php
```

- **第 1 步 环境检测**：确认 PHP 8.0 与 fileinfo 扩展就绪（缺少时在宝塔「软件商店 → PHP 8.0 → 安装扩展」中安装后重启 PHP）
- **第 2 步 填写配置**：
  - 数据库主机 / 端口 / 库名 / 账号 / 密码：填第 1 步创建的数据库
  - 表前缀：保持默认 `ad_`（向导会自动改写 SQL 中的表前缀，无需手动处理）
- **第 3 步 开始安装**：向导自动完成
  1. 写入 `.env`（数据库连接）
  2. 写入 `config/site.php`（站点安全码 authcode，**系统自动生成随机值**，用于用户登录令牌加盐，无需手动填写）
  3. 导入 `data/adlw.sql`（27 张表结构 + 最小种子数据：默认管理员、站点配置基线、支付渠道、产品目录等，**不含任何用户/订单业务数据**）
  4. 创建 `public/install/install.block` 安装锁（防止重复安装）

### 4. 安装后必做

| 事项 | 操作 |
| --- | --- |
| 修改默认管理员密码 | 后台 → 个人设置，默认账号 `admin` / `admin123456` |
| 删除安装向导 | 删除 `public/install.php` 与 `public/install/` 目录（已有安装锁，此为双保险） |
| 配置对接 | 后台 →「对接配置」，填写上游 `api_url` 与 `api_token`（见下文） |
| 开启 HTTPS | 宝塔 → SSL，申请证书并开启强制 HTTPS |
| 关闭调试 | 确认 `.env` 中 `APP_DEBUG = false` |

## 三、对接配置（核心）

本系统为**对接站**，AI 能力全部来自上游服务平台。进入后台 →「对接配置」：

| 配置项 | 说明 |
| --- | --- |
| 对接域名 api_url | 上游平台 openapi 通道根地址（需含末尾斜杠）。包内已预填演示地址 `http://lwapi2.wangkedaan.com/`，如你的上游平台不同请改为对应地址 |
| 对接 Token api_token | 上游平台签发的 openapi Bearer 凭证 |
| agent_str 前缀 agent_id_prefix | 默认 `adweb_`。系统对上游的所有请求都会携带 `agent_str = 前缀 + 本站用户ID`，用于在上游侧隔离本站用户的订单、配额与私有模板。多站共用同一上游时，各站使用不同前缀即可互不干扰 |

也可直接编辑 `config/docking.php`（后台保存与手动编辑等效）。

## 四、前端（public/pc 与 public/m）

`public/pc/`（PC 端）与 `public/m/`（H5 移动端）为已构建完成的 Nuxt 3 静态站点（预渲染 HTML + 静态资源），**部署时无需任何构建操作**。

- PC 端：`https://你的域名/pc/`；H5 移动端：`https://你的域名/m/`
- **自适应分流**：根路径 `https://你的域名/` 由后端按浏览器 UA 自动 302 到 `/m/`（移动端）或 `/pc/`（桌面端）；已打开的页面在切换设备（如 PC 转手机）时前端也会自动互相跳转
- 前端内嵌了**版本自检脚本**：HTML 不缓存、静态资源长缓存；重新上传 `public/pc`、`public/m` 覆盖后，老用户浏览器会自动检测到新版本并强制刷新，无需手动清缓存

如需修改前端源码（`frontend/` 目录，Nuxt 3，PC 与 H5 共用一套工程）：

```bash
cd frontend
npm install
npm run build           # 产物自动部署到 ../public/pc 与 ../public/m
```

可选环境变量（写入 `frontend/.env`）：

```
# 文件下载网关（如自建了下载加速网关；留空则前端直接使用上游返回的资源地址）
NUXT_DOWNLOAD_GATEWAY=https://your-download-gateway.example/download.php
```

## 五、数据库

- 全部表结构见 `data/adlw.sql`（27 张表）
- 建议为高频查询表补充索引（数据量增大前执行一次即可）：

```sql
ALTER TABLE `ad_balance_logs` ADD INDEX `idx_uid_ctime` (`user_id`, `create_time`);
ALTER TABLE `ad_orders` ADD INDEX `idx_uid_code_pay` (`user_id`, `product_code`, `pay_status`);
ALTER TABLE `ad_recharge_orders` ADD INDEX `idx_uid_pay` (`user_id`, `pay_status`);
```

- 本系统缓存使用 File 驱动（`runtime/`），**无需安装 Redis**

## 六、常见问题（FAQ）

**Q: 访问首页 404 或空白？**
运行目录未设置为 `/public`，或伪静态规则未配置。

**Q: 安装向导提示 PHP 版本不符？**
本系统仅支持 PHP 8.0.x。宝塔「网站设置 → PHP 版本」切换为 8.0。

**Q: 后台打不开 / 样式错乱？**
确认 `public/static/` 目录完整上传；浏览器强刷（Ctrl+F5）。

**Q: 修改配置后不生效？**
PHP 启用了 opcache 时可能有数秒延迟；宝塔「PHP 管理 → 重载配置」可立即生效。

**Q: 如何重装？**
删除 `.env`、`config/site.php`、`public/install/install.block`，并清空数据库后重新访问 `/install.php`。

**Q: 在线更新如何开启？**
开源版默认关闭（`config/version.php` 的 `online_update.enabled = false`，更新服务端地址在 `app/service/VersionService.php` 与 `OnlineUpdateService.php` 的 `ONLINE_UPDATE_BASE_URL` 常量中）。如需启用，自建更新服务端后修改这两处，并将 `config/version.php` 中 `security.allowed_hosts` 填入你的更新服务器域名。
